# 눈치밥 nunchi-bap · Streamlit

급식 대기 줄을 예측해서 5분 칸으로 나누는 학교용 서비스의 시연 앱입니다.
마송고등학교 모의창업 프로젝트 (박유건 · 이예니).

## 구성
- `app.py` — 학생 앱 (가입 → 사용법 → 예약 → 추천 → 확정 → 하교 후 피드백 → 기록 · 팀 · 정기 예약 · 설정)
- `pages/1_관리자.py` — 관리자 웹 (학교 설정 · 오늘 대시보드 · 운영 규칙 · 리포트 · AI 엔진 · 시뮬레이션)
- `pages/2_교실_배정표.py` — 교실 전자칠판 화면
- `nb_core.py` — 대기행렬 계산, 추천, 배식 속도 자동 보정, 저장
- `nb_ai.py` — AI 엔진 (AI ① 칸별 유입 인원 · AI ② 추천 수락 확률 · 피드백 응답률 보정 · 팀 배정 시뮬레이션)
- `nb_ui.py` — 시간표 스타일 공용 UI
- `data/state.json` — 시연 데이터 (앱이 자동으로 만듭니다)

## 로컬 실행
```
pip install -r requirements.txt
streamlit run app.py
```

## 계산 원리
- 5분 칸 정원 = μ(명/분/라인) × 라인 수 × 5분 × 안전계수 0.85
- 예상 대기 = (앞선 누적 대기 인원 + 이 칸 도착 인원) ÷ (μ × 라인 수)
- 배식 속도 자동 보정: μ오늘 = 0.8·μ어제 + 0.2·μ추정 (하교 후 피드백의 대기 구간으로 추정)

## AI 엔진 (발표 10~13장)
| | 무엇을 | 방법 |
|---|---|---|
| AI ① | 칸별 유입 인원 (예약 안 한 학생 포함) | 그래디언트 부스팅 회귀 (scikit-learn HistGradientBoosting) |
| 계산 ① | 예상 대기시간 · 신호등 | 대기행렬 (`nb_core.queue`) |
| AI ② | 추천을 받아들일 확률 | 로지스틱 회귀 |
| 계산 ② | 팀별 추천 · 배정 | 예약이 들어올 때마다 다시 계산하는 순차 배정 + 마감 후 수락 확률 높은 팀에 먼저 추천 |

- 단계: 데이터 10일 미만 **계산 운영** → 20일 미만 **자동 보정**(실제 ≈ a×예약 + b) → 20일부터 **AI 평가**. 마지막 10일 검증에서 기본 통계보다 오차가 5% 이상 작을 때만 AI로 교체.
- 입력 피처: 요일, 5분 칸, 예약 인원, 정기 예약 인원, 팀 수, 메뉴 인기도, 비, 폭염, 시험·단축 수업, 4교시 끝난 학년 수, 지난주 같은 칸 실제 인원.
- 피드백 → 실제 인원: 칸별 응답 수 ÷ 응답률 × 팀 평균 인원.
- **학습 데이터는 시연용 가상 데이터**(`make_history`, `make_rec_log`)이고 규칙이 코드에 적혀 있다. 11월 실측 후 같은 표 형식(date, slot, reserved, …, actual)으로 바꾸면 된다.
- 관리자 → 06 AI 엔진에서 "쌓인 데이터 기간"을 1~8주로 바꾸면 단계 전환과 교체 규칙을 시연할 수 있다 (5주: AI가 아직 못해서 계산 유지, 8주: AI 교체).
- 관리자 → 07 시뮬레이션: 예약률별 피크·대기, "아침 한 번 계산" vs "매번 다시 계산"(추천 칸 쏠림) 비교.
- scikit-learn이 없으면 학생 앱은 기존 계산식으로 자동으로 돌아간다.

발표 전 초기화: 관리자 → 학교 설정 → **시연 데이터 초기화**. 데이터는 서버 파일에 저장되므로 재배포하거나 앱이 잠들었다 깨면 초기화될 수 있습니다.
