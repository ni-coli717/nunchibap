# 눈치밥 모델 (AI 2개 + 계산 2개)

```
pip install -r model/requirements.txt
python -m model.run_all --seeds 5      # 보정 → 시뮬레이션 → 모델 1·2 학습 → 검증 → artifacts/results.json
```

## 흐름
"실측 데이터로 시뮬레이터를 보정하고, 시뮬레이션 데이터로 학습한 뒤, 실측 데이터로 검증했습니다."

| 단계 | 파일 | 하는 일 |
|---|---|---|
| 보정 | `calibrate.py` | `data/real/`의 실측·설문 → 배식 속도 μ, 칸별 도착 모양, 팀 크기, 추천 수락 곡선 (`artifacts/calibration.json`) |
| 시뮬레이션 | `simulate.py` | 612명 · 약 190팀 · 90일. 정기 예약(정원 70%) → 아침 예약 → 꽉 차면 추천 → 노쇼 → 대기행렬 → 하교 후 피드백 |
| 모델 1 | `train_arrivals.py` | 칸별 유입 인원. 기본 통계 · 선형회귀 · 랜덤포레스트 · XGBoost 비교, 학습 기간 마지막 10일로 최종 모델 선택 |
| 모델 2 | `train_accept.py` | 추천 수락 확률. 로지스틱 회귀(해석) vs XGBoost, 넛지 효과 표 |
| 검증 | `validate_real.py` | 피드백 추정 vs 실측 유입, 대기행렬 계산 vs 실제 대기 |

## 모델 1 · 칸별 유입 인원
- 한 행 = 날짜 × 5분 칸. 정답 = **하교 후 피드백 추정치** (앱 사용자: 응답 ÷ 응답률, 앱 안 쓰는 학생: 인원 × 실측 기간 도착 모양)
- 입력: 요일, 칸, 칸 예약 인원, 정기 예약 인원, 앞·뒤 칸 예약, 메뉴 인기도, 비, 폭염, 학사일정, 시험 날, 4교시 끝난 학년 수, 지난주 같은 칸 인원, 앱 사용률
- 분할: 앞 9일 = 실측 기간(학습 제외, 검증용) · 마지막 20일 = 테스트 · 나머지 = 학습

## 모델 2 · 추천 수락
- 한 행 = 추천 1번. 입력: 줄어드는 대기, 시간 이동, 포인트, 메시지 형태, 메뉴 인기도, 팀 인원, 팀 과거 수락률
- 시뮬레이션은 추천마다 메시지 형태와 포인트를 **무작위로** 정한다 (A/B 실험). 날짜에 따라 바꾸면 효과가 날짜와 섞여서 모델이 구분하지 못한다 → 파일럿도 이렇게 돌려야 한다

## 지금 결과 (실측 없이 가정값, seed 0)
| 모델 1 (테스트 20일) | 칸당 오차 | 신호등 일치 | 대기시간 오차 |
|---|---|---|---|
| 기본 통계 (예약 × 비율) | 19.1명 | 57% | 3.9분 |
| 선형회귀 | 10.6명 | 79% | 1.2분 |
| 랜덤포레스트 | 10.6명 | 79% | 1.9분 |
| XGBoost | 10.4명 | 81% | 2.6분 |

- 시드 5개 평균: 기본 통계 대비 오차 감소 XGBoost 44%, 선형회귀 46% → 데이터가 700행 안팎이면 선형회귀도 비슷하다
- 피드백 추정 정답 자체의 오차가 약 23% → 정확도의 한계는 모델보다 **정답 품질(응답률)**. 응답률 40% → 80%면 정답 오차 28% → 22%

| 모델 2 (테스트 25%) | AUC | 정확도 |
|---|---|---|
| 로지스틱 회귀 | 0.78 | 72% |
| XGBoost | 0.76 | 70% |
| 항상 다수 답 | 0.50 | 61% |

모든 숫자는 가정값으로 만든 시뮬레이션 결과다. `data/real/`에 실측을 넣고 다시 돌리면 바뀐다.
